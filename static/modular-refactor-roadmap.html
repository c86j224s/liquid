추출 원칙

  • 네트워크 경계는 보수적으로: 스크래핑 crate에는 순수 helper를 우선 이동하고 guarded fetch/task wiring은 루트에 남겼습니다.
  • 계약이 민감한 prompt는 고정: src/research.rs는 이동 대신 fingerprint snapshot test로 회귀를 막았습니다.
  • 저장소는 adapter부터: 전체 handler SQL을 한 번에 없애지 않고 DB/repository seam을 먼저 확보했습니다.
  • 벤치/아티팩트 정책 보존: raw benchmark output은 repo 밖에 두고 smoke summary만 검증 근거로 사용했습니다.

주의 지점

Historical fixture 하나는 여전히 untrusted입니다. 이는 이번 구조 리팩토링의 실패라기보다 연구 품질 게이트가 역사 narrative richness에 엄격하게 남아 있음을 보여주는 기준점입니다.

현재 결론

이번 브랜치는 “crate seam 확보”라는 구조 목표에 대해 커밋 가능한 녹색 경계에 도달했고, engine preset 순수 정책도 runtime crate로 이동했습니다. 더 큰 분해는 별도 wave로 잡는 편이 안전합니다.
